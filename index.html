ppl-compass

Monte um protótipo navegável do BNG People escrevendo HTML — com o azul e o dourado já corretos e as regras de acessibilidade já embutidas, para que o que sai do protótipo seja implementável sem retrabalho de design.

O que é: camada de apresentação e comportamento para telas de mentira.
O que não é: biblioteca de produção, roteador, gerenciador de estado, cliente de API.

Instalação

Dois arquivos do CDN e a página funciona. Sem npm install, sem bundler, sem passo de build — o que está no repositório é o que o navegador recebe.

Os hashes de integridade e as boas práticas estão em Uso via CDN.

Antes de começar

O pacote carrega regras de design embutidas e falha fechado em várias delas: navegação com rota ativa que não existe no menu, fluxo de efeito jurídico sem etapa de revisão, confirmação em ação reversível. Nesses casos ele não desenha meio certo — some e mostra o defeito.

Esta documentação aponta para dist/ local, então reflete o commit aberto. A galeria de blocos original continua em demo/gallery.html.

Uso via CDN jsDelivr

O pacote é servido pelo jsDelivr direto do GitHub — sem publicação, sem pipeline, sem npm. Tag nova no repositório, arquivo novo no CDN.

O bloco completo, com integridade

Use os arquivos com integrity. O hash cobre o byte exato: se o que chegar ao navegador não for o que foi publicado, a página não carrega em vez de carregar diferente.

Não use o .min

O jsDelivr gera .min.css sob demanda e avisa, no cabeçalho do próprio arquivo, para não usar SRI com arquivo gerado dinamicamente: o minificador muda de versão, o byte muda, o hash quebra e a página inteira para de carregar. Servimos o arquivo legível e travamos o byte com SRI — e os comentários das receitas são a documentação, cada um anotando o componente React de origem e a regra de acessibilidade que o sustenta.

Onde abrir

O protótipo precisa ser servido por HTTP. Abrir por file:// não funciona: o Chrome bloqueia parte das requisições. Qualquer servidor estático serve — python -m http.server resolve.

Compatibilidade

Duas últimas versões maiores de Chrome, Edge e Safari. Safari define o teto — é o último a chegar. Sem polyfill: polyfill é dependência.

Em uso: :has(), @container, color-mix() e inert — é ele que prende o foco no drawer sem gerenciar tabindex à mão. Fora por ora: aninhamento nativo de CSS. backdrop-filter sempre acompanhado de -webkit-, que o Safari exige.

Como fazer a próxima tela

  • Copie o template mais próximo.
  • Troque a rotaAtiva do JSON da navegação e a migalha do topo. São os dois lugares que dizem "onde estou", e desencontrar os dois é o defeito mais comum ao copiar.
  • Troque o miolo do <main>.
  • Confira a tag do CDN nas três URLs — protótipo publicado aponta para tag fixa, nunca para branch.

O critério que o lista.html cumpre

Ele é a tela de Folha do console, e cabe em menos de 200 linhas de HTML, sem uma linha de CSS nova e sem nenhum <script> além do init(). Se uma mudança fizer o arquivo passar de 200 linhas, o problema é falta de componente — não excesso de tela.

Os limites, ditos na cara

Os templates não guardam estado. Isso tem três consequências que não se descobrem numa demo:

  • O toast é o único registro do que aconteceu. Numa tela de verdade isso seria defeito: a lista tem que ganhar a linha, e o estado da tela tem que mudar junto.
  • Voltar uma etapa no wizard perde o que foi digitado — o formulário é redesenhado.
  • A navegação precisa de JavaScript. Com o script bloqueado o <aside> fica vazio. Se um protótipo precisar sobreviver sem JS, escreva os <a class="ppl-nav__item"> à mão: a receita CSS é a mesma.

Regras que o pacote embute

Não são preferências de estilo. Um protótipo que as viola gera retrabalho na implementação — e várias delas o pacote não deixa violar: ele falha fechado, some e mostra o defeito em vez de desenhar meio certo.

De composição

  • Um CTA primário sólido por tela. Rótulo verbo-primeiro ("Concluir admissão"), nunca "OK". Vale por superfície: um drawer aberto tem o próprio CTA.
  • No máximo um elemento dourado por tela. Dourado é acento, e acento repetido deixa de acentuar.
  • Vermelho é só erro e ação destrutiva. Nunca "chamar atenção".
  • Gradiente só em navegação, CTA de destaque, marca e selo — a lista é fechada.
  • Cards grandes para escolher caminho, não dropdown escondido. Alvo ≥ 160px.

De conteúdo

  • Estado nunca só por cor — sempre ícone + texto.
  • Dado de folha e ponto sempre em .ppl-data, com tabular-nums: matrícula, CPF/CNPJ, NSR, competência e todo valor em tabela.
  • Contador é o número real, com separador de milhar — nunca "99+". nav() recusa um contador que não seja número.
  • Competência é data civil AAAA-MM, nunca Date, que arrasta fuso. Valor monetário é string decimal no domínio: formate só na exibição.
  • Zero emoji em qualquer superfície — ícone é ícone, e vem do pacote. O build reprova, e a regra pega até o dingbat digitado no lugar do ícone de check.
  • pt-BR fixo, sem framework de i18n.

De acessibilidade

  • Alvo de toque ≥ 44px com .ppl-btn--touch. Em toque, o alvo é o link inteiro — nunca a pílula.
  • Foco visível em todo interativo, global em *:focus-visible.
  • Um modal por vez. O foco é preso marcando os irmãos como inert, então um segundo modal nasceria inerte — desenhado na tela e invisível ao teclado. Empilhar aqui não degrada, apaga.
  • Esc nunca confirma — mas cancela, porque fechar diálogo pelo teclado é requisito, não atalho de descoberta.
  • Respeita prefers-reduced-motion e prefers-reduced-transparency — nesta, o vidro vira opaco.

De processo

  • Fluxo de efeito jurídico ou financeiro termina em revisão. O Wizard falha fechado: sem a etapa revisao ele não renderiza. Um fluxo de rescisão que "esqueceu" a revisão não é um fluxo com uma tela a menos — é um fluxo que assina sem conferir.
  • Confirmação é proporcional ao risco do processo, e o risco é atributo do processo, não decisão de tela. R0 e R1 não abrem diálogo.
  • Nunca listar-e-negar: a busca global é composta pelo que o operador pode fazer.
  • O contexto que decide fica visível do início ao fim do fluxo — quem, qual CNPJ, qual competência.

De nome

Nada foi herdado do console. Lá as superfícies ainda se chamam bento e glass — nomes de decisões já revertidas: a direção Bento UI e o glassmorphism que a identidade v5 removeu da operação. Aqui cada nome descreve o que a coisa é: .ppl-card é um card, .ppl-bar é uma barra, .ppl-disclosure é o padrão ARIA que ele implementa.

O build reprova se um nome aposentado voltar ao fonte — inclusive na documentação, de onde ele volta para o código pela mão de quem copiou o exemplo.

Contraste

A meta é WCAG 2.1 AA, e o CI recalcula 16 pares a partir do tokens.css de hoje, em claro e escuro — anotação em documento não segura ninguém, porque quem troca o token deixa a anotação para trás.

Três pares herdados da paleta do console não atingem AA e estão nomeados como dívida: --ppl-ink-faint (3,12:1), --ppl-warning (3,19:1) e --ppl-success (4,41:1). A checagem mede os três a cada execução e reprova se algum piorar. Pagá-los é decisão de identidade: --ppl-ink-faint precisaria escurecer até encostar em --ppl-ink-soft, e a hierarquia de três níveis do texto viraria dois.

Superfícies e texto .ppl-card .ppl-display .ppl-data

O .ppl-card é o componente mais usado do sistema — 233 ocorrências no console. As outras superfícies são a barra fixa de topo e o fundo da página.

Card

Só levanta no hover o que é clicável. Painel estático que sobe mente sobre ser interativo, então o efeito exige um <a>, um <button> ou a classe --interactive.

Tipografia de papel

Três classes, e cada uma tem uma regra de uso que não é estética: .ppl-display só aparece em superfície emocional — saudação, sucesso, hero — e nunca em formulário, tabela ou cromo. .ppl-data é obrigatório em matrícula, CPF/CNPJ, NSR, competência e todo valor em tabela: o tabular-nums impede a coluna de dançar.

Barra e fundo

.ppl-bar é a superfície fixa de topo: branco a 92% com hairline e backdrop-filter. .ppl-canvas é o fundo do shell autenticado — três gradientes radiais azuis muito diluídos sobre o cinza-azulado.

Entrada

.ppl-enter é a única animação de entrada — sobe 10px e revela. Respeita prefers-reduced-motion: com a preferência ligada, ela simplesmente não roda.

Ícones data-ppl-icon

São 136, vindos do lucide — a biblioteca única do design system (DS-03), a mesma que o console e a PWA renderizam via lucide-react. A geometria é embutida no arquivo: o pacote não é carregado em runtime e não há requisição externa. Marque um <i> e o init() troca pelo SVG.

Os nomes são os canônicos do lucide. Alias depreciado do lucide-react resolve para o canônico — AlertTriangle vira triangle-alert, mesma geometria, nome que sobrevive. Não há alias antigo do ppl-compass: nome que não existe devolve vazio, e é assim que o erro aparece.

Em JavaScript

Por que não existe emoji

Ícone é ícone. A regra vale também para o que "parece" um símbolo tipográfico: o caractere de check digitado no lugar do ícone é exatamente o defeito que a checagem existe para pegar, e o build reprova — a faixa proibida inclui os dingbats justamente por isso.

O catálogo

Lido do próprio pacote, não de uma lista à mão.

Botões .ppl-btn

Um CTA primário sólido por tela, com rótulo verbo-primeiro — "Concluir admissão", nunca "OK". A regra vale por superfície: um drawer aberto cobre a página e tem o próprio CTA. O CI reprova dois sólidos na mesma superfície.

Hierarquia

Destaque e destruição

--hero é o CTA de destaque, o único com gradiente. --danger é só erro e ação destrutiva — nunca "chamar atenção". --gold é o acento quente, no máximo um por tela.

Tamanho, ícone e toque

--touch garante os 44px de altura mínima e é obrigatório em superfície de toque. Botão só de ícone exige aria-label.

Desabilitado

Alternância

Um botão que liga e desliga leva aria-pressed, e a receita o desenha marcado. Sem a marca visível, o atributo conta ao leitor de tela o que a tela não mostra a ninguém.

Badges e tiles .ppl-badge .ppl-icon-tile

Estado nunca só por cor. Um badge de situação leva ícone e texto — quem não distingue as cores continua lendo o estado, e quem imprime em preto e branco também.

Situação

Contador

O número real, com separador de milhar — nunca "99+". Truncar o contador esconde a ordem de grandeza justamente onde ela decide se a fila é de hoje ou do trimestre. A navegação recusa um contador que não seja número.

Tile de ícone

O quadrado arredondado antes do título, em quatro tamanhos e dois tons.

Formulário .ppl-field .ppl-input .ppl-combo

Validação de tela é espelho, não autoridade — quem recusa de verdade é o backend. min/max em campo de data é conveniência: digitação e colagem furam.

Campos

.ppl-input--data marca o campo que recebe identificador — CPF, CNPJ, matrícula, competência, valor.

Agrupamento

Checkboxes relacionados moram num <fieldset> com <legend> — é o agrupamento acessível, e o reset do pacote tira a moldura nativa que faria o agrupamento certo parecer defeito.

Combobox com busca

O <select> nativo não aceita busca, e em lista paginada na origem o item simplesmente não está lá. Este é o padrão ARIA combobox + listbox: setas navegam, Enter escolhe, Esc fecha só o popup — sem isso, um único Esc fecharia o drawer inteiro e perderia o formulário.

Envio sem persistência

O protótipo não guarda nada. data-ppl-submit intercepta o envio, fecha o painel que contém o formulário e anuncia o resultado — é o que mantém sete dos oito templates com zero JavaScript.

O limite, dito na cara: o toast é o único registro do que aconteceu, e a tela por baixo não muda. Numa tela de verdade isso seria defeito.

Alert, toast e estados .ppl-alert .ppl-toast .ppl-state

Alert — o aviso que fica na página

Toast — o aviso que passa

Região aria-live="polite", montada pelo próprio pacote. Sucesso e informação somem sozinhos; erro é persistente e traz ação de recuperação — é o requisito do design system, e é o que o console ainda não faz, onde tudo some em 4,2 s.

O toast nunca é o único registro do estado — a tela também muda. No protótipo isso não acontece, e é a consequência aceita de não haver estado.

Estados de lista

Toda lista repete os quatro. Em operação longa é proibido spinner infinito sem contexto: use barra determinada com contador.

O erro traz a saída, não só o diagnóstico: quem lê precisa saber o que fazer agora. Veja o painel de dados para trocar entre os quatro sem mexer em hidden.

Tabela e painel de dados .ppl-table .ppl-data-panel

É a receita mais copiada do console: 51 tabelas repetem a mesma máquina de quatro estados à mão. Aqui os quatro blocos são escritos uma vez e quem escolhe é o data-ppl-state do painel.

A máquina de quatro estados

Três decisões que a receita carrega

  • O cabeçalho fica fora da troca. Ele não leva data-ppl-when, de propósito: lista que perde o próprio título enquanto carrega obriga a esperar para saber o que se está esperando.
  • Só declaramos display: none, nunca um valor de display. Forçar block no bloco visível quebraria quem usa grid dentro dele — e quebraria em silêncio.
  • Estado desconhecido mostra os quatro empilhados. É para incomodar: um painel que some inteiro esconde o defeito; quatro estados um sobre o outro apontam para ele.

Um bloco pode servir a mais de um estado — data-ppl-when="vazio erro" —, porque na prática os dois costumam ser a mesma moldura com outro texto e outra ação.

Trocar por JavaScript

Colunas

.ppl-td-data para identificador, .ppl-td-num para valor — alinhado à direita e em tabular-nums, para a coluna não dançar. O scroll horizontal vive no .ppl-table-wrap, nunca na página.

Painel, choice e stat .ppl-panel .ppl-choice .ppl-stat

Painel — a moldura de ~25 telas

Anatomia fixa: tile, título e linha de apoio à esquerda; ação à direita.

Cabeçalho de página

O contexto que decide — quem, qual CNPJ, qual competência — fica visível do início ao fim do fluxo. Ele mora aqui, não numa tela anterior.

Choice — decisão de caminho

Cards grandes, alvo ≥ 160px, e não um dropdown escondido: escolher processo é a decisão mais frequente do dia, e ela não pode custar dois cliques e uma lista. Só um card por tela recebe o dourado.

Stat — número grande

Todo valor em --ppl-font-data com tabular-nums.

Disclosure — seção colapsável

Padrão ARIA: <button> dentro de <h2>, com aria-expanded e aria-controls. Fechado, o cabeçalho continua dizendo o que importa — contagem e resumo vivo. Disclosure que esconde a informação de decisão obriga a abrir tudo para conferir qualquer coisa.

Review — a lista de conferência

.ppl-review é um <dl> de chave e valor. É o que a etapa de revisão do wizard e o alvo da confirmação usam.

Navegação e busca PplCompass.nav(json)

A navegação inteira — marca, grupos, itens, ícone, rota ativa, contador e rodapé de usuário — sai de um objeto. É o que faz um template virar dez sem copiar marcação: o shell de todas as telas é a mesma lista com uma rotaAtiva diferente.

Declarativa — é a que os templates usam

Os grupos nascem recolhidos, menos o que contém a rota ativa. Recolher é gesto momentâneo de foco, não configuração: não persiste.

O item ativo carrega aria-current="page" e ganha a barra dourada — o único dourado permanente do shell.

Ela falha fechado, e é aqui que isso paga

Navegação malformada não aparece meio certa: some, e no lugar dela vem um alerta dizendo o defeito. São seis casos:

  • item sem label ou sem href;
  • grupo sem itens;
  • contador que não é número — o "99+" é exatamente o que o badge de contagem existe para evitar;
  • tabbar com mais de 5 itens, que é o teto verificado no CI do produto;
  • tabbar fora de um <nav>;
  • rotaAtiva que não existe no menu — o mais importante dos seis. Menu que não sabe onde você está é pior do que menu nenhum, porque mente com confiança.

A mesma chamada desenha a tabbar

"variante": "tabbar", o mesmo objeto: um produto não mantém duas listas de rotas. O alvo de toque é o link inteiro, ≥ 44px — nunca a pílula de 36px.

Topo — só cromo

A navegação não mora aqui. O eyebrow diz o grupo econômico ativo; a migalha diz a tela.

Busca global

Ctrl/⌘ + K — experimente agora, nesta página. O diálogo não está no HTML: o pacote monta, como faz com a região do toast. A lista sai de acoes e, sem essa chave, ela herda o que a navegação compôs — declarar as rotas duas vezes cria duas verdades que divergem na primeira rota nova.

Escape vale em qualquer ponteiro, porque fechar diálogo é acessibilidade. Todo o resto é desativado em pointer: coarse: num aparelho de dedo o ⌘K não tem como ser acionado, e o painel anunciaria teclas que não existem. Lá a porta é o botão da barra de topo.

Drawer e diálogo .ppl-drawer .ppl-dialog

O drawer é o padrão de edição de 35 telas do console. Ele abre e fecha por atributo — nenhuma linha de JavaScript na página.

O contrato de acessibilidade

  • role="dialog" + aria-modal + aria-labelledby;
  • Esc fecha, e o clique no scrim também;
  • o foco vai para o painel ao abrir e volta ao gatilho ao fechar — sem isso, fechar joga o teclado para o início do documento e a pessoa refaz o caminho inteiro;
  • o resto da página fica inert enquanto ele está aberto.
Um modal por vez. O foco é preso marcando os irmãos de cada nível como inert, então um segundo modal nasceria inerte — desenhado na tela e invisível para o teclado e para o leitor de tela. Empilhar ali não degrada, apaga. Quem tenta abrir o segundo é recusado.

Experimente

Repare no que o pacote recusa: os dois últimos botões não abrem confirmação nenhuma, e explicam por quê.

Por que R0 e R1 não abrem modal

Fadiga de confirmação é risco mapeado. Confirmar ação reversível treina o operador a clicar sem ler — e aí o modal do R3, o que realmente importa, também não é lido. Pedir confirmação demais custa a confirmação que importa. Por isso o pacote recusa, em vez de obedecer.

Sobre o Esc

Ele cancela nos dois níveis e nunca confirma. O requisito proíbe o Esc valer como confirmação; prender a pessoa dentro do diálogo seria trocar um risco por outro. No R3 o clique fora não faz nada: perder a frase digitada por um clique torto custa refazer o caminho todo.

O que mais é recusado

  • R3 sem frase — é um R2 fantasiado; o que separa os dois níveis é digitar o texto exato;
  • diálogo sem alvo — sem ele o operador confirma o diálogo, não a operação;
  • título ausente — o título diz a consequência, não a ação: "Reabrir a competência 2026-08?" e não "Tem certeza?";
  • R4 — exige step-up de autenticação, e um protótipo não tem como fazer isso de verdade;
  • um segundo modal por cima de outro.

A comparação do R3

Ignora acento, caixa e espaço sobrando: " JOSE DA silva " casa com "José da Silva". O botão destrutivo nasce travado e só habilita com o texto idêntico.

Em JavaScript

O evento de auditoria

O R3 despacha ppl:auditoria em document, com { processo, risco, alvo, quando }. Num protótipo ele não tem para onde ir — o contrato existe e está visível, e persistir é trabalho de quem construir de verdade.

Wizard new PplCompass.Wizard()

Uma decisão por etapa. Avançar sempre valida a etapa corrente; voltar é direito do operador; saltar para frente burlaria a validação e está bloqueado.

Falha fechado: fluxo de efeito jurídico ou financeiro sem etapa de revisão não renderiza — mostra o defeito. Um fluxo de rescisão que "esqueceu" a revisão não é um fluxo com uma tela a menos: é um fluxo que assina sem conferir.

Entrar no console

Clique na lua para alternar o tema — a preferência é gravada em localStorage. É dado de interface anônimo: não é cookie e não depende de consentimento.

Toda receita resolve na paleta pública aqui dentro

Dentro de .ppl-landing, tinta, borda e superfície são remapeadas para --ppl-lp-*. Sem isso um componente reusado aqui aparece meio certo: .ppl-choice__title pede --ppl-ink, que é o azul-marinho do shell e não vira no escuro — título azul-marinho sobre fundo azul-marinho some, e some em silêncio.

--ppl-primary fica de fora do remapeamento, de propósito: no escuro o azul de marca perde contraste como texto, mas continua sendo o fundo certo para texto branco. Trocar os dois juntos consertaria o link e quebraria o botão sólido.

Vidro é degradação, nunca requisito

Com prefers-reduced-transparency, .ppl-glass e os cards viram opacos — sem pedir nada a quem escreveu a página. A folha de consentimento (.ppl-sheet) já é quase opaca de propósito: texto jurídico precisa manter contraste sobre qualquer conteúdo que role por baixo.

Layout .ppl-shell .ppl-main .ppl-stack

O mínimo para compor tela. Sem utilitários atômicos — não existe .mt-4 nem .flex: se uma tela precisa de dez classes para existir, o que falta é componente, não utilitário.

Chame uma vez, depois do DOMContentLoaded. Chamar de novo depois de injetar marcação é seguro e é o que o wizard faz a cada etapa.

O que a API não tem

Nenhum gerenciador de estado, nenhum roteador, nenhum cliente de API. O protótipo é estático por decisão: os dados moram no HTML.

Atributos data-ppl-*

Quem monta o protótipo não escreve JavaScript: marca o HTML e chama init() uma vez. Sete dos oito templates têm exatamente uma linha de script.
